# Viewport Narrative Contract

Principles is a thinking system, not a sequence of decorative hero sections. A viewport should behave like a complete scene in a story: it gives the user enough context to understand the tension, enough meaning to interpret it, and a clear action that advances reality.

This contract is informed by editorial learning products that structure long material as chapters with a thesis, supporting context, and a transition. The goal is not to reproduce another product's visual identity. The goal is to make each screen carry a complete unit of meaning.

## 1. A screen is a scene, not a poster

Every primary scene should answer four questions without requiring the user to scroll backward:

1. **Where am I?** — chapter / stage / position in the cycle.
2. **What is the tension?** — the relevant Dream, Reality, Gap, disagreement, or evidence.
3. **What does it mean?** — one concise thesis that explains why this scene matters.
4. **What can I do now?** — the working surface or decision that advances the story.

Large type is allowed only when it carries meaning. Empty vertical space is not a substitute for hierarchy.

## 2. Current scene before archive

The primary route should surface the current scene before historical explanation. Past material remains visible as local context or an inspectable story-so-far, but should not force the user to travel through the whole history before reaching the work that matters now.

For `Me`, the current scene contains:

- current chapter and prompt;
- chapter thesis;
- Dream;
- observed Reality;
- active Gap, when named;
- attention signal, when present;
- the editable / actionable work for the current chapter.

The 5 Steps follow as a compact story arc for inspection, not as a progress dashboard.

## 3. Narrative density

A viewport should feel intentionally filled, not crowded and not empty.

- Prefer one strong headline plus 2–4 supporting information groups.
- Keep long-form working text in readable sans-serif type at roughly 16–18px with generous leading.
- Keep line lengths around 45–75 characters when possible.
- Avoid inner scrolling for narrative text and editable long-form fields.
- On tablet landscape, prefer one reading column for active work and use compact context rows above it.
- If content exceeds a viewport, let the document scroll naturally. Never clip content to preserve a slide-like height.

## 4. Repetition is allowed when it prevents context switching

Dream, Reality, Gap, evidence, ownership, or decision context may appear again inside a later scene when the user needs it to make the current decision. This is not duplication for decoration; it is local narrative context.

The test is simple: can the user make the current decision without scrolling several screens upward to remember what the decision is about?

## 5. Surface grammar

### Me

Dream → Reality → Gap → Diagnosis → Design → Do → Outcome → Reflection → Principle.

### Organization

Intent → Current structure → Tension → Responsibility → Decision → Consequence.

### Knowledge

Question → What we know → Evidence → Tension / disagreement → Synthesis → Decision implication.

### Learning

Experience → Reflection → Pattern → Principle → Evidence across cycles → Revision.

Each route may look different, but every primary scene must preserve the four-question completeness test: **Where / Tension / Meaning / Action**.

## 6. Review gate

Before shipping a narrative UI change, review desktop, tablet landscape, and mobile screenshots and ask:

- Is the current scene visible before a large amount of historical content?
- Is more than half the first viewport empty for no semantic reason?
- Can the user name the current tension within five seconds?
- Is the action understandable without scrolling backward?
- Is all long text readable without inner scrolling or clipping?
- Does the scene feel like a chapter in a lived story rather than a dashboard, SaaS hero, or presentation slide?
